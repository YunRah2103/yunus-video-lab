# 3. CURRENT V2 — WHY IT STILL MISSES THE REFERENCE

This is the most important section.

## A. IT STILL FEELS TOO "GENERATED SYSTEM" / MOTION-GRAPHIC

The reference feels like a creator is constantly manipulating:

- a real vehicle
- real components
- a presenter
- typography
- numbers
- crops
- reactions

V2 still feels too often like:

**designed graphic**
→ **designed graphic**
→ **designed graphic**
→ **designed graphic**

It is cleaner than V1, but still too controlled and schematic.

### Fix

Make the foreground feel more tactile and editorial.

Use:
- photographic / high-quality masked vehicle cutouts
- real mechanical component imagery
- imperfect but intentional crops
- object scale changes
- cutout movement
- presenter intrusions into the composition
- foreground overlap
- visual replacement rather than always "adding another graphic"

The viewer should feel like the editor is constantly rearranging real visual material.

---

## B. THE CAR STILL DOES NOT FEEL PHOTOGRAPHIC / DESIRABLE ENOUGH

The biggest remaining difference is asset quality.

The reference immediately reads as:

**real automotive content**

V2 still reads partly as:

**stylised explainer art**

That is not enough.

### Fix

Prioritise recognisable Porsche imagery.

For the final episode, use strong assets for:

- modern Porsche 911 exterior
- classic / early 911
- side-profile 911
- flat-six engine
- rear-engine placement
- rear wheel / driven tyre
- early 911 cornering / oversteer visual
- 1968 / 1969 wheelbase comparison
- rear suspension
- 993

- modern 911 hero ending

When discussing a component, the component should be able to **replace the car as the hero object**.

Do not keep using one generic car representation for every mechanical idea.

## C. V2 IS STILL TOO CENTRED AND BALANCED

The reference often feels more alive because the composition is not always:

CAR CENTER
↓
TEXT CENTER
↓
PRESENTER CENTER/BOTTOM

V2 still falls into that pattern too often.

### Fix

Use more composition variation:

- car pushed partly off-screen
- giant presenter crop entering from left/right
- text offset around the car
- component on one side, presenter gaze on the other
- large face crop
- car occupying 60–80% width
- presenter only partially visible
- car temporarily disappearing entirely
- stat taking over nearly the whole screen
- split comparison
- extreme close component crop
- small car + huge number
- huge car + tiny caption
- presenter overlapping the car

The reference should feel like the same few ingredients are being **recomposed constantly**.

Packet Guy must behave like an editorial tool.

## E. CAPTIONS ARE FASTER, BUT STILL TOO MUCH LIKE A CAPTION SYSTEM

The V2 event map is useful, but the typography can still feel like a reusable subtitle engine.

The reference makes text feel like part of the visual storytelling.

### Fix

Do not always put the word in the same central caption zone.

Examples:

- WRONG beside the engine
- HERE? directly at rear axle
- TRACTION huge behind/around the rear tyre
- +57 MM nearly full-screen
- SWINGS following the pendulum direction
- ROTATES rotating slightly with the car
- MULTI-LINK placed near the component
- YES. as a giant reaction/punchline

Use typography as an object.

The text can:
- move
- scale
- get cropped
- sit behind the car
- overlap presenter
- attach to an arrow
- replace another word
- snap to a component
- temporarily dominate the frame

Avoid making every word feel like the same component with different content.

## F. THE REFERENCE HAS STRONGER "OBJECT REPLACEMENT"

One reason the reference stays engaging is that the main visual object keeps changing.

→ STAT

### Fix

Track the primary foreground object for every 1–3 second span.

If the viewer has effectively been looking at "the same car" for too long, replace it.

A visual event is not only a caption change.
